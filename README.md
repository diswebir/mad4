# سامانهٔ مدیریت مدرسه «مدرسه» (Madrese)

سامانهٔ جامع، ماژولار و فارسی مدیریت مدرسه با **Node.js** که بدون نیاز به سرور اختصاصی روی **هاست اشتراکی cPanel** (Setup Node.js App / Passenger) نصب می‌شود.

- ۲۵ ماژول و **۲۰۱ قابلیت** که هرکدام را می‌توان جداگانه روشن/خاموش کرد ([فهرست کامل](docs/FEATURES.md))
- رابط کاملاً راست‌چین با فونت **وزیرمتن**، تقویم **شمسی** و حالت تاریک
- سه نقش: **مدیر** (همه‌چیز را مدیریت می‌کند)، **معلم** (کلاس‌های خود) و **دانش‌آموز** (پنل شخصی)
- پروندهٔ کامل دانش‌آموز: مشخصات، تلفن‌ها، اطلاعات پدر/مادر/سرپرست، تماس اضطراری، سلامت، مدارک، یادداشت‌ها و انتقال‌ها
- حضور و غیاب روزانه/زنگی، کارنامه، تکالیف، تیکت پشتیبانی، پیام، اطلاعیه، اعلان، تقویم، نظرسنجی، مالی، کتابخانه، سرویس، مرخصی، انضباط، سلامت، مشاوره، گزارش‌ها و جستجوی سراسری
- **ویزارد نصب وب** (مانند وردپرس) + نصب از خط فرمان
- پایگاه دادهٔ **SQLite** (بدون نیاز به چیزی) یا **MySQL/MariaDB**
- بهینه: فشرده‌سازی gzip، کش قالب‌ها و فایل‌های ایستا، صفحه‌بندی، ایندکس‌های پایگاه داده، حالت WAL برای SQLite
- **دادهٔ نمونهٔ فارسی** (۱۲ معلم، ۱۰ کلاس، ۲۰۰ دانش‌آموز با اولیا، ۴۵ روز حضور و غیاب، آزمون‌ها، تکالیف، تیکت‌ها، شهریه‌ها، کتاب‌ها و…)

## ۱) پیش‌نیازها

| مورد | حداقل |
|---|---|
| Node.js | ۱۸ (پیشنهادی ۲۰ یا ۲۲) |
| پایگاه داده | هیچ (SQLite داخلی) یا MySQL 5.7+/MariaDB 10.3+ |
| فضای دیسک | حدود ۱۰۰ مگابایت به‌علاوهٔ فایل‌های آپلودی |

درایور SQLite به‌صورت خودکار از بین این‌ها انتخاب می‌شود: `better-sqlite3` (اگر نصب شود) ← `node:sqlite` (Node ≥ 22.5) ← `sql.js` (WebAssembly، همه‌جا کار می‌کند). پس حتی اگر هاست اجازهٔ کامپایل ماژول‌های بومی را ندهد، سامانه کار می‌کند.

## ۲) نصب روی هاست cPanel (گام به گام)

1. **بارگذاری فایل‌ها**
   - فایل ZIP پروژه را در *File Manager* داخل پوشه‌ای مانند `~/madrese` (خارج از `public_html`) استخراج کنید.
   - پوشهٔ `node_modules` را آپلود **نکنید**؛ در گام ۴ نصب می‌شود.

2. **ساخت برنامهٔ Node.js**
   - در cPanel به **Software → Setup Node.js App** بروید و روی *Create Application* بزنید.
   - *Node.js version*: ۱۸ یا بالاتر (ترجیحاً ۲۰/۲۲)
   - *Application mode*: `Production`
   - *Application root*: `madrese` (همان پوشهٔ گام ۱)
   - *Application URL*: دامنه یا زیردامنهٔ مورد نظر (مثلاً `school.example.com`)
   - *Application startup file*: `app.js`
   - روی *Create* بزنید.

3. **متغیرهای محیطی (اختیاری)**
   در همان صفحه می‌توانید *Environment variables* اضافه کنید. هیچ‌کدام اجباری نیست؛ ویزارد نصب تنظیمات را در `storage/config.json` می‌نویسد.

   | متغیر | توضیح |
   |---|---|
   | `NODE_ENV` | `production` (پیش‌فرض cPanel) |
   | `PORT` / `HOST` | Passenger خودش تعیین می‌کند؛ دست نزنید |
   | `APP_URL` | آدرس کامل سایت (برای لینک ایمیل‌ها) |
   | `DB_CLIENT` | `sqlite` یا `mysql` (در صورت تمایل به تنظیم با متغیر به‌جای ویزارد) |
   | `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_PREFIX` | مشخصات MySQL |
   | `DB_FILENAME` | مسیر فایل SQLite (پیش‌فرض `storage/madrese.sqlite`) |
   | `APP_KEY` | کلید رمزنگاری نشست (ویزارد خودش می‌سازد) |
   | `TZ_OFFSET` | پیش‌فرض `+03:30` |

4. **نصب وابستگی‌ها**
   - در صفحهٔ برنامه روی **Run NPM Install** بزنید (یا در ترمینال/SSH: دستوری که بالای صفحه نمایش داده می‌شود را اجرا و سپس `npm install --omit=dev` بزنید).
   - اگر `better-sqlite3` به‌خاطر نبود کامپایلر نصب نشد، نگران نباشید؛ اختیاری است.

5. **(فقط برای MySQL)** از **MySQL® Databases** یک پایگاه داده و کاربر با همهٔ دسترسی‌ها بسازید و مشخصات را یادداشت کنید.

6. **اجرای ویزارد نصب**
   - روی *Restart* بزنید و دامنه را در مرورگر باز کنید؛ به‌طور خودکار به `/install` هدایت می‌شوید.
   - مراحل: بررسی پیش‌نیازها ← انتخاب پایگاه داده (SQLite/MySQL و درایورهای موجود) ← اطلاعات مدرسه و حساب مدیر ← دادهٔ نمونه (اختیاری) ← پایان.
   - نصب بدون نیاز به ری‌استارت در همان لحظه فعال می‌شود. برای اطمینان می‌توانید یک‌بار دیگر *Restart* بزنید.

7. **پس از نصب**
   - با نام کاربری مدیر وارد شوید و از **تنظیمات ← ماژول‌ها و قابلیت‌ها** امکانات مورد نیاز را روشن/خاموش کنید.
   - اطلاعات مدرسه، لوگو، رنگ سازمانی، پیامک و ایمیل را از **تنظیمات** کامل کنید.
   - از **تنظیمات ← پشتیبان‌گیری** به‌صورت دوره‌ای نسخهٔ پشتیبان بگیرید.

### نکات cPanel
- پوشه‌های `storage/` و `public/uploads/` باید قابل نوشتن باشند (معمولاً به‌صورت پیش‌فرض هستند).
- برای **ری‌استارت** می‌توانید فایل `tmp/restart.txt` را لمس (touch) کنید یا دکمهٔ Restart را بزنید.
- اگر صفحهٔ «It works! NodeJS» یا خطای ۵۰۳ دیدید، *Application startup file* را بررسی کنید که دقیقاً `app.js` باشد و `npm install` کامل اجرا شده باشد. لاگ‌ها در `stderr.log` داخل پوشهٔ برنامه قرار می‌گیرند.
- سامانه از `process.env.PORT` استفاده می‌کند و به سوکتی که Passenger می‌دهد گوش می‌دهد؛ نیازی به پورت اختصاصی نیست.
- وضعیت سرویس: `https://your-domain/healthz` یک JSON برمی‌گرداند.

## ۳) نصب روی سرور/کامپیوتر شخصی

```bash
git clone <repo> madrese && cd madrese
npm install --omit=dev
npm start            # http://localhost:3000 → ویزارد نصب
```

### نصب از خط فرمان (بدون ویزارد)

```bash
# SQLite + دادهٔ نمونه
node scripts/install.js --school "دبیرستان نمونه" --admin admin --password admin123 --name "مدیر مدرسه" --demo

# MySQL
node scripts/install.js --mysql --host 127.0.0.1 --db madrese --user root --pass secret \
  --school "دبیرستان نمونه" --admin admin --password admin123 --demo

# نصب مجدد روی پایگاه دادهٔ موجود (--force) یا با پاک‌کردن کامل جدول‌ها (--fresh)
node scripts/install.js --force --fresh --school "..." --admin admin --password ... --demo
```

سایر اسکریپت‌ها:

| دستور | کار |
|---|---|
| `npm run migrate` | ساخت/به‌روزرسانی جدول‌ها و ایندکس‌ها |
| `npm run seed` | بارگذاری دادهٔ نمونه روی نصب موجود |
| `npm run reset -- --yes [--all]` | پاک‌کردن داده‌ها (با `--all` کاربران و تنظیمات هم حذف می‌شوند) |
| `node scripts/features.js` | تولید `docs/FEATURES.md` از مانیفست ماژول‌ها |
| `npm test` | اجرای تست‌های یکپارچه روی نمونهٔ در حال اجرا با دادهٔ نمونه |

## ۴) حساب‌های نمونه (حالت دمو)

| نقش | نام کاربری | رمز |
|---|---|---|
| مدیر | `admin` (یا آنچه در نصب وارد کردید) | `admin123` |
| معلم | `teacher1` تا `teacher12` | `123456` |
| دانش‌آموز | شمارهٔ دانش‌آموزی، مثلاً `40001` | `123456` |

در حالت دمو این اطلاعات روی صفحهٔ ورود نمایش داده می‌شود. برای حذف دادهٔ نمونه از **تنظیمات ← دادهٔ نمونه** یا `npm run reset -- --yes` استفاده کنید.

## ۵) معماری و ساختار پوشه‌ها

```
app.js                 نقطهٔ ورود (Passenger / node app.js)
src/app.js             ساخت اپ Express، میان‌افزارها، بارگذاری ماژول‌ها
src/core/              هستهٔ مشترک: db (درایورهای sqlite/mysql + QueryBuilder)، auth، csrf، session-store،
                       settings، modules (فعال/غیرفعال‌سازی)، crud (CRUD عمومی)، jalali، notify، upload، …
src/installer/         ویزارد نصب وب و نصب‌کنندهٔ مشترک
src/modules/<key>/     هر ماژول: index.js (مانیفست: قابلیت‌ها، منو)، routes.js، views/
src/views/             قالب‌ها (layouts، partials، crud، errors)
database/schema.js     تعریف جدول‌ها و ایندکس‌ها (مستقل از نوع پایگاه داده)
database/seeds/demo.js دادهٔ نمونهٔ فارسی
public/                فایل‌های ایستا (Bootstrap 5 RTL، Bootstrap Icons، Chart.js، وزیرمتن، JS/CSS سامانه)
storage/               config.json، فایل SQLite، آپلودها، پشتیبان‌ها، لاگ‌ها (خارج از Git)
scripts/               install / migrate / seed / reset / features
tests/                 تست‌های یکپارچه (HTTP) برای همهٔ جریان‌های اصلی
docs/FEATURES.md       فهرست کامل ۲۰۱ قابلیت
```

**پشتهٔ فنی:** Express 5، EJS + express-ejs-layouts (رندر سمت سرور، بدون مرحلهٔ build)، express-session با ذخیرهٔ نشست در پایگاه داده، helmet، compression، multer، bcryptjs، jalaali-js، mysql2، sql.js / node:sqlite / better-sqlite3، nodemailer.

### ماژولار بودن
- هر ماژول در `src/modules/<key>/index.js` یک مانیفست دارد: `key`، `name`، `features[]` (با کلیدهای نقطه‌دار مانند `attendance.excuses`)، `menu[]` و `routes`.
- وضعیت ماژول‌ها/قابلیت‌ها در جدول `module_states` نگهداری و در حافظه کش می‌شود.
- در مسیرها با `modules.requireEnabled('finance.payments')` و در قالب‌ها با `enabled('finance.payments')` بررسی می‌شود؛ منوها خودکار پنهان می‌شوند و مسیرهای ماژول خاموش صفحهٔ «ماژول غیرفعال» می‌دهند.
- ماژول `core/system` و قابلیت‌های علامت‌خوردهٔ «همیشه فعال» قابل خاموش‌شدن نیستند.

### امنیت
- هش رمز با bcrypt، محدودیت تلاش ورود، کپچای ساده، اجبار تغییر رمز اول، ثبت تاریخچهٔ ورود
- توکن CSRF روی همهٔ فرم‌ها و درخواست‌های AJAX، helmet، کوکی `httpOnly`/`sameSite`
- کنترل دسترسی مبتنی بر نقش در همهٔ مسیرها؛ معلم فقط به کلاس‌های خود و دانش‌آموز فقط به پروندهٔ خود دسترسی دارد
- آپلودها با محدودیت نوع/حجم و نام‌گذاری تصادفی در `storage/uploads` (خارج از وب‌روت) و ارائه از طریق `/files/...` با بررسی دسترسی

## ۷) پرسش‌های متداول

**آیا به MySQL نیاز دارم؟** خیر. SQLite برای مدارس تا چند هزار دانش‌آموز کاملاً کافی است و با حالت WAL و ایندکس‌ها سریع کار می‌کند. هر زمان خواستید می‌توانید با نصب مجدد به MySQL بروید.

**چطور پشتیبان بگیرم؟** از **تنظیمات ← پشتیبان‌گیری** (برای SQLite کپی امن فایل، برای MySQL خروجی JSON از همهٔ جدول‌ها) یا کپی دستی پوشهٔ `storage/`.

**چطور فونت/رنگ را عوض کنم؟** از **تنظیمات ← ظاهر** رنگ اصلی و پوستهٔ پیش‌فرض را تغییر دهید. فونت وزیرمتن به‌صورت محلی در `public/fonts` قرار دارد و نیازی به اینترنت ندارد.

**به‌روزرسانی؟** فایل‌های جدید را جایگزین کنید (به‌جز `storage/`)، `npm install --omit=dev` و سپس `npm run migrate` و Restart.
