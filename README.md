# سامانهٔ مدیریت مدرسه «مدرسه» (Madrese)

سامانهٔ جامع، ماژولار و فارسی مدیریت مدرسه با **Node.js** که بدون نیاز به سرور اختصاصی روی **هاست اشتراکی cPanel** (Setup Node.js App / Passenger) نصب می‌شود.

- ۳۰ ماژول و **۲۵۰ قابلیت** که هرکدام را می‌توان جداگانه روشن/خاموش کرد ([فهرست کامل](docs/FEATURES.md))
- رابط کاملاً راست‌چین با فونت **وزیرمتن**، تقویم **شمسی** و حالت تاریک
- پنج نقش: **مدیر** (همه‌چیز)، **کارمند/معاون** (با سمت و مجوزهای ریز)، **معلم** (کلاس‌های خود)، **دانش‌آموز** (پنل شخصی) و **ولی** (پنل فرزندان)
- پروندهٔ کامل دانش‌آموز: مشخصات، تلفن‌ها، اطلاعات پدر/مادر/سرپرست، تماس اضطراری، سلامت، مدارک، یادداشت‌ها و انتقال‌ها
- حضور و غیاب روزانه/زنگی، کارنامه با قفل نوبت و تاریخچهٔ تغییر نمره، تکالیف، دفتر کلاسی و گزارش تدریس، تیکت پشتیبانی، پیام، اطلاعیه، اعلان، تقویم، نظرسنجی، مالی، کتابخانه، سرویس، مرخصی، انضباط، سلامت، مشاوره، گزارش‌ها و جستجوی سراسری
- اسناد رسمی با سربرگ، شمارهٔ سریال و استعلام عمومی (گواهی اشتغال به تحصیل، نامه، کارنامهٔ رسمی، ریزنمرات، دفتر حضور و غیاب)
- پیش‌ثبت‌نام آنلاین بدون نیاز به ورود (`/apply`) با کد رهگیری، بررسی/پذیرش و تبدیل به پروندهٔ دانش‌آموز
- زمان‌بند کارها (پیامک غیبت، یادآوری شهریه/تکلیف/کتاب، پشتیبان‌گیری خودکار، پاک‌سازی) با سه روش اجرا و بازیابی رمز با کد یک‌بارمصرف
- **ویزارد نصب وب** (مانند وردپرس) + نصب از خط فرمان
- پایگاه دادهٔ **SQLite** (بدون نیاز به چیزی) یا **MySQL/MariaDB**
- بهینه: فشرده‌سازی gzip، کش قالب‌ها و فایل‌های ایستا، صفحه‌بندی، ایندکس‌های پایگاه داده، حالت WAL برای SQLite
- **دادهٔ نمونهٔ فارسی** (۱۴ معلم، ۲ کارمند با سمت، ۱۰ کلاس، ۲۰۰ دانش‌آموز، ۴۰+ حساب ولی، ۴۵ روز حضور و غیاب، ۲۵۰ آزمون، ~۱۹۰۰ گزارش تدریس، تکالیف، تیکت‌ها، شهریه‌ها، کتاب‌ها، اسناد، پیش‌ثبت‌نام‌ها و…)

## ۱) پیش‌نیازها

| مورد | حداقل |
|---|---|
| Node.js | ۱۸ (پیشنهادی ۲۰ یا ۲۲) |
| پایگاه داده | هیچ (SQLite داخلی) یا MySQL 5.7+/MariaDB 10.3+ |
| فضای دیسک | حدود ۱۰۰ مگابایت به‌علاوهٔ فایل‌های آپلودی |

درایور SQLite به‌صورت خودکار از بین این‌ها انتخاب می‌شود: `better-sqlite3` (اگر نصب شود) ← `node:sqlite` (Node ≥ 22.5) ← `sql.js` (WebAssembly، همه‌جا کار می‌کند). پس حتی اگر هاست اجازهٔ کامپایل ماژول‌های بومی را ندهد، سامانه کار می‌کند.

## ۲) نصب روی هاست cPanel (گام به گام)

1. **بارگذاری فایل‌ها**
   - فایل ZIP پروژه را در *File Manager* داخل پوشه‌ای مانند `~/madrese` (خارج از `public_html`) استخراج کنید.
   - پوشهٔ `node_modules` را آپلود **نکنید**؛ در گام ۴ نصب می‌شود.

2. **ساخت برنامهٔ Node.js**
   - در cPanel به **Software → Setup Node.js App** بروید و روی *Create Application* بزنید.
   - *Node.js version*: ۱۸ یا بالاتر (ترجیحاً ۲۰/۲۲)
   - *Application mode*: `Production`
   - *Application root*: `madrese` (همان پوشهٔ گام ۱)
   - *Application URL*: دامنه یا زیردامنهٔ مورد نظر (مثلاً `school.example.com`)
   - *Application startup file*: `app.js`
   - روی *Create* بزنید.

3. **متغیرهای محیطی (اختیاری)**
   در همان صفحه می‌توانید *Environment variables* اضافه کنید. هیچ‌کدام اجباری نیست؛ ویزارد نصب تنظیمات را در `storage/config.json` می‌نویسد.

   | متغیر | توضیح |
   |---|---|
   | `NODE_ENV` | `production` (پیش‌فرض cPanel) |
   | `PORT` / `HOST` | Passenger خودش تعیین می‌کند؛ دست نزنید |
   | `APP_URL` | آدرس کامل سایت (برای لینک ایمیل‌ها) |
   | `DB_CLIENT` | `sqlite` یا `mysql` (در صورت تمایل به تنظیم با متغیر به‌جای ویزارد) |
   | `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_PREFIX` | مشخصات MySQL |
   | `DB_FILENAME` | مسیر فایل SQLite (پیش‌فرض `storage/madrese.sqlite`) |
   | `APP_KEY` | کلید رمزنگاری نشست (ویزارد خودش می‌سازد) |
   | `TZ_OFFSET` | پیش‌فرض `+03:30` |

4. **نصب وابستگی‌ها**
   - در صفحهٔ برنامه روی **Run NPM Install** بزنید (یا در ترمینال/SSH: دستوری که بالای صفحه نمایش داده می‌شود را اجرا و سپس `npm install --omit=dev` بزنید).
   - اگر `better-sqlite3` به‌خاطر نبود کامپایلر نصب نشد، نگران نباشید؛ اختیاری است.

5. **(فقط برای MySQL)** از **MySQL® Databases** یک پایگاه داده و کاربر با همهٔ دسترسی‌ها بسازید و مشخصات را یادداشت کنید.

6. **اجرای ویزارد نصب**
   - روی *Restart* بزنید و دامنه را در مرورگر باز کنید؛ به‌طور خودکار به `/install` هدایت می‌شوید.
   - مراحل: بررسی پیش‌نیازها ← انتخاب پایگاه داده (SQLite/MySQL و درایورهای موجود) ← اطلاعات مدرسه و حساب مدیر ← دادهٔ نمونه (اختیاری) ← پایان.
   - نصب بدون نیاز به ری‌استارت در همان لحظه فعال می‌شود. برای اطمینان می‌توانید یک‌بار دیگر *Restart* بزنید.

7. **پس از نصب**
   - با نام کاربری مدیر وارد شوید و از **تنظیمات ← ماژول‌ها و قابلیت‌ها** امکانات مورد نیاز را روشن/خاموش کنید.
   - اطلاعات مدرسه، لوگو، رنگ سازمانی، پیامک و ایمیل را از **تنظیمات** کامل کنید.
   - از **تنظیمات ← پشتیبان‌گیری** به‌صورت دوره‌ای نسخهٔ پشتیبان بگیرید.

### نکات cPanel
- پوشه‌های `storage/` و `public/uploads/` باید قابل نوشتن باشند (معمولاً به‌صورت پیش‌فرض هستند).
- برای **ری‌استارت** می‌توانید فایل `tmp/restart.txt` را لمس (touch) کنید یا دکمهٔ Restart را بزنید.
- اگر صفحهٔ «It works! NodeJS» یا خطای ۵۰۳ دیدید، *Application startup file* را بررسی کنید که دقیقاً `app.js` باشد و `npm install` کامل اجرا شده باشد. لاگ‌ها در `stderr.log` داخل پوشهٔ برنامه قرار می‌گیرند.
- سامانه از `process.env.PORT` استفاده می‌کند و به سوکتی که Passenger می‌دهد گوش می‌دهد؛ نیازی به پورت اختصاصی نیست.
- وضعیت سرویس: `https://your-domain/healthz` یک JSON برمی‌گرداند.
- **کارهای زمان‌بندی‌شده روی هاست اشتراکی:** Passenger برنامه را پس از مدتی بی‌کاری می‌خواباند و تیک داخلی متوقف می‌شود. در **cPanel ← Cron Jobs** این دستور را هر ۵ دقیقه اضافه کنید (مسیر `node` را از صفحهٔ Setup Node.js App بردارید):
  `*/5 * * * * cd ~/madrese && /opt/alt/alt-nodejs20/root/usr/bin/node scripts/cron.js >> storage/logs/cron.log 2>&1`
  یا در **سیستم ← کارهای زمان‌بندی‌شده** روش اجرا را روی «cron بیرونی» بگذارید و نشانی `/cron?token=...` را به یک سرویس cron وب بدهید.
- برای **بازیابی رمز با پیامک** باید در **تنظیمات ← پیامک** درگاه را فعال کنید؛ در غیر این صورت کدها از طریق ایمیل (SMTP) ارسال می‌شوند.

## ۳) نصب روی سرور/کامپیوتر شخصی

```bash
git clone <repo> madrese && cd madrese
npm install --omit=dev
npm start            # http://localhost:3000 → ویزارد نصب
```

### نصب از خط فرمان (بدون ویزارد)

```bash
# SQLite + دادهٔ نمونه
node scripts/install.js --school "دبیرستان نمونه" --admin admin --password admin123 --name "مدیر مدرسه" --demo

# MySQL
node scripts/install.js --mysql --host 127.0.0.1 --db madrese --user root --pass secret \
  --school "دبیرستان نمونه" --admin admin --password admin123 --demo

# نصب مجدد روی پایگاه دادهٔ موجود (--force) یا با پاک‌کردن کامل جدول‌ها (--fresh)
node scripts/install.js --force --fresh --school "..." --admin admin --password ... --demo
```

سایر اسکریپت‌ها:

| دستور | کار |
|---|---|
| `npm run migrate` | ساخت/به‌روزرسانی جدول‌ها و ایندکس‌ها |
| `npm run seed` | بارگذاری دادهٔ نمونه روی نصب موجود |
| `npm run reset -- --yes [--all]` | پاک‌کردن داده‌ها (با `--all` کاربران و تنظیمات هم حذف می‌شوند) |
| `node scripts/features.js` | تولید `docs/FEATURES.md` از مانیفست ماژول‌ها |
| `npm test` | اجرای تست‌های یکپارچه روی نمونهٔ در حال اجرا با دادهٔ نمونه |

## ۵) معماری و ساختار پوشه‌ها

```
app.js                 نقطهٔ ورود (Passenger / node app.js)
src/app.js             ساخت اپ Express، میان‌افزارها، بارگذاری ماژول‌ها
src/core/              هستهٔ مشترک: db (درایورهای sqlite/mysql + QueryBuilder)، auth، csrf، session-store،
                       settings، modules (فعال/غیرفعال‌سازی)، crud (CRUD عمومی)، jalali، notify، upload، …
src/installer/         ویزارد نصب وب و نصب‌کنندهٔ مشترک
src/modules/<key>/     هر ماژول: index.js (مانیفست: قابلیت‌ها، منو)، routes.js، views/
src/views/             قالب‌ها (layouts، partials، crud، errors)
database/schema.js     تعریف جدول‌ها و ایندکس‌ها (مستقل از نوع پایگاه داده)
database/seeds/demo.js دادهٔ نمونهٔ فارسی
public/                فایل‌های ایستا (Bootstrap 5 RTL، Bootstrap Icons، Chart.js، وزیرمتن، JS/CSS سامانه)
storage/               config.json، فایل SQLite، آپلودها، پشتیبان‌ها، لاگ‌ها (خارج از Git)
scripts/               install / migrate / seed / reset / features / cron
tests/                 تست‌های یکپارچه (HTTP) برای همهٔ جریان‌های اصلی
docs/FEATURES.md       فهرست کامل ۲۵۰ قابلیت
```

**پشتهٔ فنی:** Express 5، EJS + express-ejs-layouts (رندر سمت سرور، بدون مرحلهٔ build)، express-session با ذخیرهٔ نشست در پایگاه داده، helmet، compression، multer، bcryptjs، jalaali-js، mysql2، sql.js / node:sqlite / better-sqlite3، nodemailer.

### ماژولار بودن
- هر ماژول در `src/modules/<key>/index.js` یک مانیفست دارد: `key`، `name`، `features[]` (با کلیدهای نقطه‌دار مانند `attendance.excuses`)، `menu[]` و `routes`.
- وضعیت ماژول‌ها/قابلیت‌ها در جدول `module_states` نگهداری و در حافظه کش می‌شود.
- در مسیرها با `modules.requireEnabled('finance.payments')` و در قالب‌ها با `enabled('finance.payments')` بررسی می‌شود؛ منوها خودکار پنهان می‌شوند و مسیرهای ماژول خاموش صفحهٔ «ماژول غیرفعال» می‌دهند.
- ماژول `core/system` و قابلیت‌های علامت‌خوردهٔ «همیشه فعال» قابل خاموش‌شدن نیستند.

### امنیت
- هش رمز با bcrypt، محدودیت تلاش ورود، کپچای ساده، اجبار تغییر رمز اول، ثبت تاریخچهٔ ورود
- توکن CSRF روی همهٔ فرم‌ها و درخواست‌های AJAX، helmet، کوکی `httpOnly`/`sameSite`
- کنترل دسترسی مبتنی بر نقش + مجوزهای ریز (بخش بعد) در همهٔ مسیرها؛ معلم فقط به کلاس‌های خود و دانش‌آموز/ولی فقط به پروندهٔ خود دسترسی دارد
- آپلودها با محدودیت نوع/حجم و نام‌گذاری تصادفی در `storage/uploads` (خارج از وب‌روت) و ارائه از طریق `/files/...` با بررسی دسترسی (فقط لوگوی مدرسه عمومی است)

### مدل دسترسی و مجوزها
| نقش | دسترسی |
|---|---|
| `admin` | همه‌چیز، بدون استثنا |
| `staff` (کارمند) | اجتماع مجوزهای **سمت** (`positions.permissions`) و **مجوزهای اختصاصی کاربر** (`users.permissions`). کارمندی که نه سمت دارد و نه مجوز اختصاصی، مجموعهٔ پیش‌فرض کارمندی را می‌گیرد: همهٔ مجوزها به‌جز مدیریت کاربران/سمت‌ها/معلمان، قفل نمرات، جلسات محرمانهٔ مشاوره و بخش سیستم |
| `teacher` | مبتنی بر نقش و محدود به کلاس‌ها/درس‌های خودش (تدریس یا سرپرستی) |
| `student` / `parent` | مبتنی بر نقش و محدود به پروندهٔ خود / فرزندان (ولی با `?child=` بین فرزندان جابه‌جا می‌شود) |

- کلیدهای مجوز در `src/core/permissions.js` (گروه‌های افراد، آموزش، ارتباطات، امور دانش‌آموزی، مالی، سیستم) تعریف شده‌اند؛ مثل `students.manage`، `attendance.manage_all`، `exams.lock`، `lessons.manage`، `documents.issue`، `admissions.manage`.
- سمت‌های پیش‌فرض (معاون آموزشی، معاون پرورشی و انضباطی، دفتردار و مسئول ثبت‌نام، حسابدار، مشاور، کتابدار، مسئول فناوری) در اولین اجرا ساخته می‌شوند و از **کاربران ← سمت‌ها** قابل ویرایش‌اند؛ در فرم هر کاربر می‌توان سمت و «مجوزهای اختصاصی» را تعیین کرد.
- در مسیرها: `auth.requireRoleOrPermission(['admin'], 'students.manage')`؛ در قالب‌ها: `can('students.manage')`. منوها بر اساس نقش **یا** مجوز نمایش داده می‌شوند.

### زمان‌بند کارها (Scheduler / Cron)
کارهای دوره‌ای (پیامک تجمیعی غیبت به اولیا، یادآوری مهلت تکالیف، شهریهٔ معوق و کتاب‌های دیرکرد، بستن خودکار تیکت‌ها، پشتیبان‌گیری خودکار، پاک‌سازی داده‌های موقت و خلاصهٔ روزانهٔ مدیر) در **سیستم ← کارهای زمان‌بندی‌شده** فهرست می‌شوند؛ هرکدام ساعت اجرا، روشن/خاموش، تاریخچهٔ اجرا و دکمهٔ «اجرای دستی» دارد. سه روش اجرا:
1. **تیک داخلی** (پیش‌فرض): خود برنامه هر دقیقه بررسی می‌کند؛ روی Passenger تا زمانی که برنامه بیدار است کار می‌کند.
2. **cron هاست**: `node scripts/cron.js` را در cPanel ← Cron Jobs هر ۵ دقیقه اجرا کنید (برای هاست‌هایی که برنامه را به خواب می‌برند).
3. **سرویس cron بیرونی**: `GET https://domain/cron?token=...` (توکن در همان صفحه نمایش داده می‌شود). قفل اجرا مانع تداخل دو روش می‌شود.

### قفل نمرات و تاریخچهٔ تغییر
با `exams.lock` مدیر می‌تواند یک **نوبت** را نهایی/قفل کند (**آموزش ← نوبت‌ها**): پس از قفل، معلمان نمرات را فقط می‌بینند، نوشتن‌ها ۴۰۳ می‌شود و ویرایش مدیر نیازمند ثبت **دلیل تغییر** است. با `exams.history` هر تغییر نمره (قبلی/جدید/چه‌کسی/چرا) در `grade_changes` ثبت و در **آزمون‌ها ← تغییرات نمره** و تاریخچهٔ هر آزمون نمایش داده می‌شود؛ کارنامه برچسب «نهایی/موقت» می‌گیرد. حذف نوبتی که آزمون دارد یا قفل است ممکن نیست.

### بازیابی رمز عبور
با `auth.password_reset` و تنظیم «امنیت ← بازیابی رمز»، کاربر در `/auth/forgot` نام کاربری/موبایل خود را وارد می‌کند؛ کد ۶ رقمی (۱۰ دقیقه اعتبار، حداکثر ۳ درخواست در ساعت برای هر کاربر و ۹ برای هر IP، ۵ تلاش برای هر کد) با پیامک (یا ایمیل در نبود پیامک) ارسال می‌شود. در حالت پیامک «log» متن پیامک در **سیستم ← لاگ پیامک** دیده می‌شود. حداقل طول رمز از تنظیمات قابل تغییر است.

### اسناد رسمی و سربرگ
ماژول **اسناد و گواهی‌ها** (`documents`) انواع سند را با **شمارهٔ سریال** یکتا (`گ-۱۴۰۵-۰۰۰۱`، پیشوندها: گ گواهی، ن نامه، ک کارنامه، ر ریزنمرات، ل دفتر حضور) و **کد استعلام** ۱۰ رقمی صادر می‌کند؛ هر سند از طریق `/documents/verify/<کد>` بدون ورود قابل استعلام است (معتبر / باطل‌شده / نامعتبر). سربرگ (عنوان‌ها، منطقه، لوگو، امضا، مهر، سمت امضاکننده) و قالب گواهی اشتغال به تحصیل با جانگهدارهای `{student} {father} {student_number} {national_id} {class} {grade} {school} {date} {year} {recipient}` در **تنظیمات ← اسناد و سربرگ** تعریف می‌شود. کارنامهٔ رسمی به‌صورت **snapshot** ذخیره می‌شود تا تغییرات بعدی نمرات روی سند صادرشده اثر نگذارد؛ ابطال با ذکر دلیل، واترمارک «باطل شد» می‌زند. دانش‌آموز/ولی اسناد خود را در **گواهی‌های من** می‌بیند و معلم می‌تواند ریزنمرات/دفتر حضور کلاس خود را چاپ کند.

### پیش‌ثبت‌نام و پذیرش
ماژول `admissions` فرم عمومی **`/apply`** (بدون ورود، با کپچا، اعتبارسنجی کد ملی/موبایل/تاریخ شمسی، محدودیت ۵ درخواست در ساعت برای هر IP، پیوست اختیاری) را ارائه می‌کند؛ پس از ثبت، **کد رهگیری** `AP-1405-00001` صادر و (در صورت فعال‌بودن پیامک) برای پدر/سرپرست ارسال می‌شود. خانواده با کد و کد ملی در **`/apply/track`** وضعیت را پی می‌گیرد. مدیر یا کارمند دارای `admissions.manage` در **افراد ← پیش‌ثبت‌نام** درخواست‌ها را بررسی می‌کند (در حال بررسی، نیازمند مدارک، پذیرفته، رد — با یادداشت عمومی و پیامک) و برای درخواست پذیرفته‌شده با انتخاب کلاس، **ثبت‌نام قطعی** می‌زند: پروندهٔ دانش‌آموز و حساب کاربری ساخته و اطلاعات اولیا منتقل می‌شود. باز/بسته‌بودن ثبت‌نام، سال تحصیلی، پایه‌های مجاز، متن راهنما و مدارک لازم در **تنظیمات ← پیش‌ثبت‌نام** است؛ لینک فرم روی صفحهٔ ورود نمایش داده می‌شود.

### دفتر کلاسی و گزارش تدریس
ماژول `lessons` برای هر جلسهٔ **برنامهٔ هفتگی** یک گزارش تدریس (موضوع، سرفصل مرتبط، شرح، تکلیف) نگه می‌دارد. معلم در **تدریس امروز** جلسات امروزش را می‌بیند و با ثبت سریع تکمیل می‌کند؛ مدیر همان صفحه را به‌صورت «وضعیت ثبت معلمان» می‌بیند. **سرفصل‌ها و بودجه‌بندی** (ساعت و بازهٔ برنامه‌ریزی‌شده برای هر درس) مبنای گزارش **پیشرفت تدریس** (درصد سرفصل‌های تدریس‌شده، سرفصل‌های عقب‌افتاده) است. **جلسات ثبت‌نشده** برنامهٔ هفتگی را با گزارش‌ها مقایسه می‌کند (روزهای کاری، بدون تعطیلات تقویم) و به تفکیک معلم نرخ ثبت می‌دهد. معلم فقط تا «مهلت ویرایش» (پیش‌فرض ۷ روز، تنظیمات آموزشی) می‌تواند گزارش خود را ویرایش/حذف کند؛ مدیر همیشه. دانش‌آموز و ولی در **درس‌های من** می‌بینند هر روز چه درسی داده شده و چه تکلیفی تعیین شده است. دفتر کلاسی ماهانهٔ هر کلاس (روز × زنگ) قابل چاپ است.

## ۷) پرسش‌های متداول

**آیا به MySQL نیاز دارم؟** خیر. SQLite برای مدارس تا چند هزار دانش‌آموز کاملاً کافی است و با حالت WAL و ایندکس‌ها سریع کار می‌کند. هر زمان خواستید می‌توانید با نصب مجدد به MySQL بروید.

**چطور پشتیبان بگیرم؟** از **تنظیمات ← پشتیبان‌گیری** (برای SQLite کپی امن فایل، برای MySQL خروجی JSON از همهٔ جدول‌ها) یا کپی دستی پوشهٔ `storage/`.

**چطور فونت/رنگ را عوض کنم؟** از **تنظیمات ← ظاهر** رنگ اصلی و پوستهٔ پیش‌فرض را تغییر دهید. فونت وزیرمتن به‌صورت محلی در `public/fonts` قرار دارد و نیازی به اینترنت ندارد.

**به‌روزرسانی؟** فایل‌های جدید را جایگزین کنید (به‌جز `storage/`)، `npm install --omit=dev` و سپس `npm run migrate` و Restart.
