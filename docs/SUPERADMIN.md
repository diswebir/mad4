# کنسول سازنده (مدیر ارشد / Super Admin)

از نسخهٔ **۱.۲.۰** هر نصب یک حساب «سازنده» دارد که برای فروشنده/پشتیبان سامانه است و از مدیر مدرسه جداست. این سند روال نصب، امنیت، کارهای روزمره و بازیابی دسترسی را شرح می‌دهد.

## مدل کار

| | مدیر مدرسه (`admin`) | سازنده (`is_super`) |
|---|---|---|
| ورود | `/auth/login` | فقط `/console/login` (در فرم عادی پذیرفته نمی‌شود) |
| دیده‌شدن | برای همه | **برای هیچ‌کس** — در فهرست کاربران، جستجو، گیرندگان پیام/اعلان، گزارش فعالیت، ورودها، آمار داشبورد و خروجی‌ها وجود ندارد |
| ماژول‌ها و قابلیت‌ها | فقط مشاهدهٔ کاتالوگ + «درخواست فعال‌سازی» (`/support/modules`) | فعال/غیرفعال‌سازی (`/system/modules`) و تأیید درخواست‌ها (`/console/requests`) |
| تنظیمات | مدرسه، آموزشی، ارتباطات، خدمات، مالی، کاربران، ظاهر، امنیت، تولدها، پرداخت، اسناد، پیش‌ثبت‌نام | همهٔ موارد + **پیامک، ایمیل، پشتیبان بیرونی، نگهداری و دیسک، همهٔ تنظیمات (پیشرفته)، خروجی/ورودی JSON** |
| نگهداری | پشتیبان‌گیری/بازگردانی، زمان‌بند، لاگ پیامک، صف اعلان، گزارش فعالیت، دادهٔ نمونه | + به‌روزرسانی از پنل، حالت تعمیر، لاگ خطاهای سرور، اطلاعات سامانه |
| ورود به جای کاربر | کاربران غیرمدیر | **هر کاربری** (حتی مدیر) از فهرست کاربران یا با نام کاربری در داشبورد کنسول |
| گزارش مشکل | دکمهٔ پایین‌چپ همهٔ صفحه‌ها (همهٔ نقش‌ها) | مشاهده، پاسخ، تغییر وضعیت، یادداشت داخلی (`/console/reports`) |

مدل فروش: سامانه یک‌بار فروخته می‌شود و حساب سازنده نزد فروشنده می‌ماند. وقتی مدرسه ماژولی بخواهد، مدیر از «ماژول‌های سامانه» درخواست می‌دهد، فروشنده پس از توافق از کنسول آن را فعال می‌کند و مدیر اعلان می‌گیرد. **هیچ سامانهٔ لایسنس/قفل سخت‌افزاری وجود ندارد.**

## ساخت حساب سازنده

- **ویزارد نصب وب** → گام «اطلاعات مدرسه و مدیر» → بخش اختیاری «حساب سازنده (پشتیبانی)».
- **خط فرمان هنگام نصب**:
  ```bash
  node scripts/install.js --school "..." --admin admin --password ... \
    --super-user vendor --super-password 'Vendor#12345' --super-name "پشتیبانی سامانه"
  ```
- **بعد از نصب** (روی سرور، از پوشهٔ برنامه):
  ```bash
  node scripts/superadmin.js create vendor 'Vendor#12345' --name "پشتیبانی سامانه" --email you@example.com
  ```

قواعد: نام کاربری `a-z 0-9 _ .` (۳ تا ۴۰ نویسه) و متفاوت از مدیر؛ رمز **حداقل ۱۰ نویسه** (bcrypt با هزینهٔ ۱۲). می‌توانید چند حساب سازنده داشته باشید؛ همگی در «امنیت کنسول» فهرست می‌شوند.

## ورود و امنیت کنسول

1. آدرس `https://domain/console/login` را باز کنید (در منوها لینک نمی‌شود؛ آن را به مدرسه ندهید).
2. پس از رمز، در صورت فعال‌بودن، کد ۶ رقمی TOTP یا یک کد پشتیبان خواسته می‌شود.
3. در «کنسول ← امنیت کنسول»:
   - **تأیید دومرحله‌ای (TOTP)**: QR را با Google/Microsoft Authenticator یا Aegis اسکن کنید، کد را وارد کنید و **۸ کد پشتیبان** را چاپ/ذخیره کنید (هر کد یک‌بار مصرف است). رمز TOTP با AES-256-GCM و کلید برنامه (`appKey` در `config.json`) رمزگذاری شده در پایگاه داده نگه داشته می‌شود.
   - **IPهای مجاز** (`superadmin_allow_ips`): فهرست IP یا پیشوند (مثل `5.75.` یا `2a01:`)؛ درخواست به `/console/*` از IP دیگر **۴۰۴** می‌گیرد. برای جلوگیری از قفل‌شدن، فهرستی که IP فعلی خودتان در آن نباشد ذخیره نمی‌شود.
   - **مدت نشست کنسول** (`superadmin_session_hours`، پیش‌فرض ۱۲): پس از آن حتی با کوکی معتبر، دوباره باید وارد شوید.
   - **ایمیل هشدار** (`superadmin_alert_email`): هر ورود موفق/ناموفق به کنسول و استفاده از کد پشتیبان، ایمیل می‌شود (نیاز به تنظیم SMTP).
   - **تغییر رمز** با رمز فعلی.
4. محدودیت تلاش: به ازای نام کاربری و نیز سراسری برای هر IP (`login_max_attempts` / `login_lock_minutes`). همهٔ ورودها در «ورودهای کنسول» با IP و مرورگر ثبت می‌شوند و از گزارش ورود مدیر مخفی‌اند.

### چرا مدیر مدرسه نمی‌تواند سازنده بسازد یا ببیند؟
- ستون `users.is_super` از فرم‌های کاربر/ورودی اکسل/درخواست‌های API حذف می‌شود (mass-assignment ممکن نیست).
- همهٔ پرس‌وجوهای فهرست/جستجو/گیرنده/آمار شرط `is_super = 0` دارند؛ صفحهٔ ویرایش/حذف/ریست/جانشینیِ سازنده برای مدیر **۴۰۴** است.
- **بازگردانی پشتیبان توسط مدیر** نمی‌تواند ردیف سازنده، جدول `module_states` و کلیدهای محافظت‌شدهٔ تنظیمات را تغییر دهد (`restoreTables` با گزینهٔ `protectSuper`). فقط بازگردانی از نشست سازنده کامل است.
- مسیرهای مخصوص سازنده پاسخ عمومی **۴۰۴** می‌دهند (نه ۴۰۳) تا وجودشان لو نرود.

> **محدودیت ذاتی**: اگر مدرسه خودش به فایل‌ها/پایگاه داده روی هاست دسترسی داشته باشد (نصب روی هاست خودش)، می‌تواند با `scripts/superadmin.js` حساب جدید بسازد. این یک محدودیت فنی برای هر نرم‌افزار self-hosted است؛ برای کنترل کامل، سامانه را روی هاست خودتان میزبانی کنید.

## کارهای روزمره

| کار | کجا |
|---|---|
| دیدن گزارش‌های خطا، تصویر، آدرس صفحه، مرورگر و خطاهای اخیر سرور | کنسول ← گزارش‌های خطا (فیلتر نوع/وضعیت/جستجو) |
| پاسخ به گزارش (کاربر اعلان می‌گیرد) / یادداشت داخلی / تغییر وضعیت | صفحهٔ هر گزارش |
| فعال‌کردن ماژول درخواستی مدیر (پیش‌نیازها خودکار فعال می‌شوند، مدیر اعلان می‌گیرد) | کنسول ← درخواست‌های ماژول |
| تنظیمات فنی (پیامک، ایمیل، پشتیبان بیرونی، نگهداری، همهٔ کلیدها) | تنظیمات ← زبانه‌های فنی (فقط در نشست سازنده دیده می‌شوند) |
| به‌روزرسانی نسخه از پنل، حالت تعمیر، لاگ خطاها، اطلاعات سرور | منوی کنسول |
| ورود به جای کاربر | کاربران ← آیکون «ورود به جای کاربر»، یا داشبورد کنسول ← نام کاربری |
| بازگشت از جانشینی | نوار نارنجی بالای صفحه ← «بازگشت به کنسول سازنده» |

در حالت جانشینی، همهٔ تغییرات با نام کاربر هدف **و** شناسهٔ سازنده (`activity_logs.impersonator_id`) ثبت می‌شوند و در «گزارش فعالیت» سازنده با برچسب «(به جای …)» دیده می‌شوند. اجبار تغییر رمز کاربر هدف در حالت جانشینی اعمال نمی‌شود.

## گزارش مشکل (ویجت کاربران)

- دکمهٔ گرد قرمز پایین‌چپ هر صفحه (ماژول `support`، قابلیت `support.widget`) برای همهٔ کاربران واردشده به‌جز سازنده.
- فیلدها: نوع (خطا/پیشنهاد/سؤال)، موضوع، شرح (≥ ۱۰ نویسه)، **یک تصویر PNG/JPG/WebP تا ۵ مگابایت**؛ آدرس صفحه، اندازهٔ نمایشگر و User-Agent خودکار پیوست می‌شود.
- سقف ارسال هر کاربر در ساعت: `support_max_per_hour` (پیش‌فرض ۱۰). متن راهنمای داخل پنجره: `support_contact_text`.
- تصاویر در `storage/uploads/support/` ذخیره می‌شوند و فقط سازنده و خودِ گزارش‌دهنده می‌توانند آن‌ها را ببینند.
- کاربر در «منوی کاربری ← گزارش‌های من» (`/support/my`) وضعیت و پاسخ را می‌بیند.

## خط فرمان: `scripts/superadmin.js`

```bash
node scripts/superadmin.js list                      # فهرست حساب‌های سازنده و وضعیت ۲FA
node scripts/superadmin.js create <user> <pass> [--name ..] [--email ..]
node scripts/superadmin.js password <user> <new-pass>  # بازنشانی رمز (نشست‌های فعال بسته می‌شوند)
node scripts/superadmin.js 2fa-off <user>             # خاموش‌کردن ۲FA وقتی گوشی/کدها را از دست داده‌اید
node scripts/superadmin.js disable|enable <user>
node scripts/superadmin.js delete <user>
node scripts/superadmin.js allow-ips "5.75.1.2, 2a01:"  # یا "" برای برداشتن محدودیت IP
```

برای اجرا روی cPanel: Terminal یا SSH → `cd ~/madrese` (مسیر برنامه) → `source` کردن محیط Node که Setup Node.js App نشان می‌دهد → دستورها را اجرا کنید.

## بازیابی دسترسی

| مشکل | راه حل |
|---|---|
| رمز سازنده فراموش شده | `node scripts/superadmin.js password vendor 'NewPass#2025'` |
| ۲FA/کدهای پشتیبان در دسترس نیست | `node scripts/superadmin.js 2fa-off vendor` سپس دوباره فعال کنید |
| IP شما تغییر کرده و کنسول ۴۰۴ می‌دهد | `node scripts/superadmin.js allow-ips ""` |
| حساب غیرفعال شده | `node scripts/superadmin.js enable vendor` |
| هیچ حساب سازنده‌ای وجود ندارد (نصب قدیمی) | `node scripts/superadmin.js create ...` — جدول‌ها هنگام اولین اجرای نسخهٔ جدید خودکار مهاجرت کرده‌اند |

## کلیدهای تنظیمات مرتبط

`superadmin_allow_ips`، `superadmin_alert_email`، `superadmin_session_hours`، `support_contact_text`، `support_max_per_hour`، `module_request_note` — فقط در نشست سازنده («امنیت کنسول» یا زبانهٔ «همهٔ تنظیمات») قابل ویرایش‌اند و بازگردانی پشتیبان توسط مدیر آن‌ها را تغییر نمی‌دهد.

## تست

`tests/flow-superadmin.js` (بیش از ۱۲۰ بررسی): ورود فقط از کنسول، ۴۰۴ برای مدیر، نامرئی‌بودن، ویجت گزارش با تصویر و سقف حجم/تعداد، درخواست و فعال‌سازی ماژول، جانشینی، TOTP و کد پشتیبان، محافظ قفل‌شدن IP، محدودیت تلاش و اسکریپت خط فرمان. برای اجرای تست‌ها نصب دمو باید با `--super-user vendor --super-password 'Vendor#12345'` انجام شده باشد.
